# Sherpa catalog audit — every voice installable & usable offline (#92)

Working doc for [issue #92](https://github.com/AACTools/rust-tts-wrapper/issues/92).
The German Piper path (#82, v1.9.0) is the worked example; this audit
is Phase 1: what each family needs, where the gaps are, and what
"readiness" must mean per model. The audit table is **generated** —
`scripts/sherpa-catalog-audit.py` reads the pinned registry; regenerate
on registry bumps and paste below.

## Readiness taxonomy (the catalog surface)

A catalog entry alone does not mean a voice is ready (#92's premise).
Each model gets a readiness value, surfaced through
`tts_get_sherpa_models_json` alongside `g2p_enabled`:

| value | meaning | example |
|---|---|---|
| `ready` | install + first use works offline with the listed assets | kokoro-en (bundled lexicon); German piper after bundle provision |
| `needs_bundle` | wrapper G2P applies once a VoiceGarden bundle is provisioned (`tts_provision_sherpa_g2p_bundle`) | `piper-fr_FR-*` once fr is validated |
| `needs_assets` | family-specific assets beyond the archive are required (vocoder, voices.bin, reference audio) — the installer must fetch them | matcha (vocoder), zipvoice (vocos) |
| `unverified` | downloads exist but no offline-synthesis validation has been recorded for this family/locale yet | most MMS locales |
| `blocked:<reason>` | something is broken or missing upstream: url missing/dead, no checksum, licensing unclear, no front-end | `floravox-student` (no sha256s — catalog repo issue) |

`g2p_enabled` stays as-is (the wrapper front-end question); readiness
is the *installer* question and subsumes it.

## Findings → work items

**A. Piper locales with published bundles (the #82 pattern, ~215 voices):**
fr×28, pt×28, es×27, nl×24, fa×19, it×12, ru×12, sv×10, ca×9, cs×7,
sw×3 (de×51 done). Per locale: (1) phoneme mapping audit against a
representative model's `tokens.txt` (the Phase 2 ladder + bake-off
harness already exist — `examples/sherpa_g2p_bakeoff.rs`); (2) **text
normalization per language** — the digit/decimal rules are German;
each locale needs its own (fr `quatre-vingt-dix`, es `veintitrés`,
decimal separators vary); (3) validation word set + whisper
round-trip; (4) allowlist row + validated flip. **Licensing gate:**
es/pt/it/ru + ca bundles are Wiktionary-derived → CC BY-SA relabel
first ([voicegarden-lexicons#1](https://github.com/AACTools/voicegarden-lexicons/issues/1));
de/fr/nl/sv/sw/cs/fa provenance needs the same per-locale audit
([voicegarden-lexicons#3](https://github.com/AACTools/voicegarden-lexicons/issues/3)).

**B. MMS (1,139 models):** native character/lexicon front-end — no
VoiceGarden bundle needed. Assets: the wrapper's vits-family config
already handles it. Gaps: **0/1139 have sha256** in the registry
(catalog-repo fix; Dasher currently special-cases `mmsDirectory`),
and the 66 `unknown`-language entries need classification.
Readiness = `unverified` until per-locale offline synthesis is
recorded; spot-check a representative set, not all 1,139.

**C. Checksum gaps (catalog repo):** 76 vits + 10 floravox-student +
2 pocket + 2 matcha + 1,139 mms models lack `sha256` — file against
[sherpa-onnx-tts-models](https://github.com/AACTools/sherpa-onnx-tts-models).

**D. Bundle-less Piper languages:** pl×26 (a real gap — popular
locale, no bundle; gruut has no pl pack; wiktionary-derived pl
bundle would be new data → voicegarden-lexicons), ar/is/hu/ne/vi/hi/
kk/tr/fi/uk… each needs the #3 treatment (source, license, mapping)
before any bundle exists. Not wrapper work until bundles publish.

**E. Non-Piper families:** kokoro/kitten/matcha/zipvoice/pocket/
supertonic ship their own front-ends — readiness is `ready` where the
archive is complete and checksummed (kokoro, kitten, zipvoice mostly
are), `needs_assets` where a vocoder/reference is separate (matcha's
vocoder, zipvoice's shared vocos — the wrapper already resolves
both), `blocked:no-sha` where checksums are missing.

**F. English piper (143 voices):** currently the #66/#67 lexicon path
(auto-generated from the eng-US bundle). #82's follow-up to migrate
English to the codepoints path (fixing English OOV/numbers the same
way) folds into item A as locale `en`.
