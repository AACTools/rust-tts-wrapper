# Language bindings for the rust-tts-wrapper C ABI

Every binding wraps the **flat C ABI** declared in
[`include/tts_wrapper.h`](../include/tts_wrapper.h) (generated by cbindgen —
`cargo build` refreshes it). One library, one ABI, five ways to reach it.

> **ABI stability:** none promised yet. The surface tracks the Rust crate
> minor version; breaking changes are announced in release notes (the
> boundary callback was consolidated in v0.4.1, for example). All consumers
> are in-repo or in projects we maintain.

## The surface at a glance

| Area | Symbols |
|---|---|
| Lifecycle | `tts_create`, `tts_destroy` |
| Synthesis | `tts_speak`, `tts_speak_ssml`, `tts_speak_sync`, `tts_synth_to_bytes`, `tts_synth_to_wav`, `tts_synth_to_bytes_measured`, `tts_free_bytes` |
| Control | `tts_stop`, `tts_pause`, `tts_resume` |
| Settings | `tts_set_voice`, `tts_set_rate`, `tts_set_pitch`, `tts_set_volume` |
| Events | `tts_set_on_audio`, `tts_set_on_boundary` (7-arg incl. `estimated`), `tts_set_on_mark`, `tts_set_on_viseme`, `tts_set_on_start`, `tts_set_on_end`, `tts_set_on_error` |
| Enumeration | `tts_get_voices`/`tts_free_voices`, `tts_get_engine_count`, `tts_get_engines`/`tts_free_engines`, `tts_get_engine_setups_json` (GH #68: typed setup fields + capabilities, JSON) |
| Errors | `tts_get_last_error` (null ctx → global error; `NULL` = no error), `tts_get_last_error_code` (stable u32, GH #69), `tts_get_last_error_detail_json` (code/name/message/displayMessage/engineId/fieldKey), `tts_free_string` |
| Credentials | `tts_check_credentials` (1 = Verified, 0 = Rejected, 2 = Unverified, -1 = check failed → detail, GH #69) |

Conventions that hold across the ABI:

- **Null-hardening:** every setter accepts a null ctx as a no-op; every
  out-pointer API returns non-zero instead of crashing on null args.
- **Ownership:** arrays and byte buffers returned by the ABI are freed by
  the matching `tts_free_*`; error strings are borrowed from the ctx.
- **Callbacks:** all callbacks are cdecl C function pointers taking a
  `void *userdata`; out-parameters are annotated in the header docs.

## Building the library

```sh
cargo build --release --no-default-features --features system,cloud   # Linux
cargo build --release --no-default-features --features avsynth,cloud  # macOS
cargo build --release --no-default-features --features sapi,cloud     # Windows
```

Artifacts: `librust_tts_wrapper.so` / `librust_tts_wrapper.dylib` /
`rust_tts_wrapper.dll` (+ `.a` staticlib). Prebuilt binaries ship with each
[GitHub release](https://github.com/AACTools/rust-tts-wrapper/releases)
for every supported platform:

| Platform | Targets | Engines | Artifact |
|---|---|---|---|
| Linux | x86_64, aarch64 | system+cloud (+sherpaonnx x86_64) | `.so` + `.a` |
| macOS | x86_64, aarch64 | avsynth+cloud (+sherpaonnx) | `.dylib` + `.a` |
| Windows | x86_64, aarch64, i686 | sapi+cloud (+sherpaonnx) | `.dll` + `.lib` |
| Android | arm64-v8a, armeabi-v7a, x86_64, x86 (API 24+) | cloud | `.so` + `.a` |
| iOS | arm64 device, arm64 simulator | cloud | `RustTtsWrapper.xcframework` + `.a` |

Mobile notes: the cloud feature is pure Rust (rustls — no OpenSSL), so the
NDK/Apple builds need no system dependencies. The iOS XCFrameworks bundle
the device + simulator staticlibs with the C header; drag them into Xcode.

## The bindings

| Directory | Package | Loads via | Test suite |
|---|---|---|---|
| [`c/`](c/) | none (reference) | link-time, `-lrust_tts_wrapper` | `make test` (C harness, `-Wall -Wextra -Werror`) |
| [`python/`](python/) | `tts_wrapper.py` | ctypes `CDLL` | inline ctypes smoke |
| [`dotnet/`](dotnet/) | `RustTtsWrapper.Bindings` (NuGet) | P/Invoke (+ `TTS_WRAPPER_LIB` resolver, `runtimes/{rid}/native`) | `dotnet test` (xunit) |
| [`swift/`](swift/) | SwiftPM `RustTtsWrapper` | link-time (`TTS_WRAPPER_LIB_DIR`), module `CRustTtsWrapper` | `swift test` (XCTest) |
| [`nodejs/`](nodejs/) | `@aactools/tts-wrapper` (npm) | koffi dlopen (`TTS_WRAPPER_LIB` or search path) | `npm test` (node:test) |

All six suites assert the **same contract** (engine enumeration, lifecycle,
setters, callback registration, deterministic failure with a dummy cloud
key — for `tts_synth_to_bytes_measured` too), so a regression in the ABI
trips every suite, and the C harness additionally verifies the header
compiles as clean C11.

## Running the suites

```sh
# 1. Rust conformance (the ABI itself)
cargo test --test ffi_conformance --test ffi_lifecycle --test ffi_safety

# 2. C harness
(cd bindings/c && make test)

# 3. Node
(cd bindings/nodejs && npm install && npm test)

# 4. .NET (needs the dotnet SDK)
(cd bindings/dotnet && dotnet test)
#   with an explicit library: TTS_WRAPPER_LIB=/path/to/lib.so dotnet test

# 5. Swift (macOS; needs Xcode toolchain)
(cd bindings/swift && TTS_WRAPPER_LIB_DIR=$PWD/../../target/debug swift test)
```

CI (`.github/workflows/bindings.yml`) runs the full matrix on every push to
main and on PRs.

## Which binding should I use?

- **Rust app/plugin:** depend on the crate directly; the C ABI exists for
  non-Rust hosts.
- **C/C++ app:** link the cdylib, include `tts_wrapper.h`. See
  `bindings/c/tts_abi_harness.c` for a complete worked example.
- **Python:** `bindings/python/tts_wrapper.py` (ctypes, zero dependencies).
- **.NET / AAC apps on Windows:** the NuGet package bundles the x64 + x86
  DLLs; `TtsClient` is the low-level client, `RustTtsClient` is a
  drop-in `DotNetTtsWrapper.AbstractTtsClient` adapter.
- **Apple platforms:** SwiftPM package; in an Xcode app build the staticlib
  and import the header as module `rust_tts_wrapper`.
- **Node/Electron:** `@aactools/tts-wrapper` (koffi-based; no node-gyp).

## Local-model management (#102)

One engine-agnostic surface for every local engine compiled into the
build — catalogue, unified availability, one install path, ctx-free
installed-voice catalogue:

| FFI | what it does |
|---|---|
| `tts_models_json(engine_id?)` | catalogue (install state + `availability`) |
| `tts_model_info_json(engine_id?, model_id)` | one entry |
| `tts_model_install(engine_id, model_id, progress, cancelled, ud)` | verify → fetch (resumable, sha256) → extract → atomic swap; synchronous, one install per process |
| `tts_model_uninstall(engine_id, model_id)` | remove files + neutral manifest |
| `tts_models_dir(engine_id)` | models dir (`TTS_MODELS_DIR` override) |
| `tts_search_models_json(query, limit)` | substring search |
| `tts_installed_voice_catalog_json()` | installed models as voices — no credentials |
| `tts_create_for_model(engine_id, model_id)` | client for a catalogued model |

Bindings wrap it idiomatically:

- **Node:** `TtsClient.localModels()` / `.installModel(id, {onProgress, cancelled})` / `.forModel()` (koffi-probed, additive)
- **Python:** `TTSClient.local_models()` / `.install_model(progress=, cancelled=)` / `.for_model()`
- **.NET:** `TtsClient.GetLocalModels()` / `.InstallModelAsync(progress, cancellationToken)` / `.CreateForModel()`
- **Swift:** `TtsClient.localModelsJSON()` / `.installModel(onProgress:cancelled:)` / `.createForModel()`

### Adopting an app's existing installs (#106)

Apps that shipped their own model layout (Dasher's
`Dasher/Speech/Models`) migrate in three steps: move/copy the verified
files to `<engine models dir>/<model id>` (set `TTS_MODELS_DIR` first if
the app container dictates the root), call **adopt** (the wrapper
validates the files its engine needs and writes the neutral
`.installed` manifest from the registry digest — model ids are
preserved, so saved voice selections keep resolving), then delete the
old layout. The app's own verification markers (e.g.
`.dasher-verified-model`) stay the app's — the neutral manifest is the
wrapper's.

- **Node:** `TtsClient.adoptModel(engineId, modelId)`
- **Python:** `TTSClient.adopt_model(engine_id, model_id)`
- **.NET:** `TtsClient.AdoptModel(engineId, modelId)`
- **Swift:** `TtsClient.adoptModel(engineId:modelId:)`

Install semantics for bundle-requiring voices (#106): the G2P bundle
provisions BEFORE the install commits; on failure the install reports a
retryable error, keeps any previous working install, and retains the
verified download so a retry skips straight to the bundle. English
voices degrade to the auto-lexicon path instead of failing.

Availability vocabulary (a superset rename of the sherpa `readiness`):
`ready | needs_download | needs_bundle | needs_assets` (+ `missing`) `|
unverified | blocked` (+ `reason`) `| wrong_engine`. Floravox entries
carry `experimental: true`.

## Engine feature sets

Engines are compile-time cargo features; the `tts_get_engines` enumeration
reflects what was compiled in. The CI matrices build:

- Linux: `system,cloud` (speech-dispatcher + cloud engines)
- macOS: `avsynth,cloud`
- Windows: `sapi,cloud`

Credentials are passed as a JSON object string at `tts_create` time; each
engine's required keys are listed in `tts_get_engines`
(`credential_keys_json`).
